# 《系统是被打出来的》· 系统设计实战手册

系统不是设计出来的，是被流量打出来的。主线：抢票平台「秒抢」0 → 亿级用户的挨打史。
五机制：值班现场与决策点 / 病历卡 / 嵌入式模拟器 / trade-off 权衡题 / **交卷练习**（先写后揭晓，全书唯一要求从空白页产出的机制）。

**纯静态 HTML，无构建依赖，可直接 GitHub Pages 部署。** 入口：`index.html`。

## 成品结构

| 路径 | 内容 |
|---|---|
| `index.html` | 目录 + 导读（五机制说明、三条阅读路径、事实边界声明） |
| `ch01.html` … `ch16.html` | 正文 16 章，七段式 |

部署时只需 `*.html` + `assets/`。

## 独立内容终审（七轮）

由一个**未参与写作**的独立 Codex 实例（read-only 沙箱）按 `tasks/content-review.md` 通读 23 页，
重点查脚本查不出来的三条：自测解析是否拆解诱人错项 / D1 信息量是否够读者判断 / D2 每个选项是否都有账单。
**首轮结论为「不通过」**，共七轮往返后判定**「内容校验：通过」**。

修掉的内容级缺陷（全部由终审发现，非作者自查）：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `ch12` | **量纲错误**：请求数与 QPS 混算，「1000万 × 10% × 5% × 20% = 1万 QPS」——百分比相乘不改变量纲 |
| 2 | `ch15` | **技术错误**：「写入安全的充要条件：任一时刻至多一个多数派」——5 节点有 C(5,3)=10 个合法多数派且可同时在线；安全来自「任意两个必相交」，且只是必要条件 |
| 3 | `level1` | **越界主张**：标题「四层是空的」与正文自相矛盾（正文写第 4 层"存在，将近 24 小时"）；官方称其为 the alternative |
| 4 | `level4` | **定性过度**：把 GitHub 事故称为「教科书式脑裂」「没有任何组件出故障」——官方无同时双主证据，且起点正是一台 *failing* 100G 光设备 |
| 5 | `ch10` | 库存不变量把凭证历史状态与当前槽位写进同一等式，RELEASED 会被双计数 |
| 6 | `level2` | 架构图误画成全部 API 都经 placement；实际只有 PUT 用它 |
| 7 | `ch16` | D2 的 C 选项支配 A/B，违反「权衡题没有明显最优解」 |
| 8 | `level2` | D1 把影响预览说成「无效」，过度否定 |
| 9 | `ch12` | 修复后新引入：30 万请求 < 6 万票，D2 失去权衡张力 → 网关配额改为 30 万，供需比 5:1 |
| 10 | `ch12` | 「候选数 / 实际入队数 / 释放速率」三个量混用；「请求数」被直接说成「人数」 |
| 11 | `ch12` | 去重顺序错误：去重不保数量，不能先取百分比再去重 → 改为「先去重、再按配额截断」，百分比降为事后观测值 |
| 12 | `ch12` | 公式 `min(入口 × ∏通过率, 各层配额)` 对多层漏斗不成立 → 改为逐层递推 `xᵢ = min(xᵢ₋₁ × pᵢ, 配额ᵢ)` |

`BIBLE.md` 的 ch12 / ch15 两处规格也同步修正——**错误源头在规格，不只在页面**。

### 真实事故红线（QUALITY.md 第二节）

四个关卡的事实**只取自官方原始复盘**：GitLab 官方 postmortem、AWS 官方 Summary、
SEC 对 Knight Capital 的行政令、GitHub 官方 post-incident analysis。原文已留档在
`sources/raw/`，每个事实性陈述在页面上挂来源角标、在 FACTS 文件里可查到出处。

**构建中据此修正过骨架的两处表述：**

1. **关卡一**：SKELETON 原写「五层备份**全部失效**」。官方复盘不支持这个说法——
   五条路径里前三条没能兑现（复制两侧皆已清空 / S3 桶为空 / 数据库未启用 Azure 快照），
   但**两份 LVM 快照都仍在**，团队是在"丢近 24 小时"与"丢约 6 小时"之间做选择。
   页面按此改写；**注意也不能写成「四层是空的」**——自动 LVM 快照存在且可用，
   官方称之为 the alternative。准确表述：制度准备的恢复点太旧，
   一次与灾备无关的临时快照反而成了最佳选择。
2. **关卡二**：SKELETON 原写「连 AWS 状态页自己的图标都加载不出」。官方复盘只说
   SHD 管理控制台依赖 S3 导致无法更新状态，未提图标。页面按原文改写为依赖自举问题。

## 已知限制

- **`bible-check.py` 的 C 段（契约级公式）是弱校验。** 它只确认某个高辨识度字符串存在
  （如 ch16 查「演练」、ch10 查「真相」、ch06 查「配额」），**不能证明 BIBLE 要求的数字代入
  真的做了**。公式代入的实际证据来自那一轮全书数字审计，不是 C 段变绿。
  后续维护者改公式时，请重跑数字审计而不是只看 C 段。
- **正文通读范围：** 16 章的**决策点（D1/D2）与自测题解析**已逐条通读复核；
  值班现场叙事、原理阐述与复盘时间线为**抽样通读**（ch01–ch05、ch10、ch12、ch16 及四个关卡全文，
  其余章节按数字与结构校验覆盖）。
- **未做浏览器目检。** 深色模式与移动端宽度的逐页人工目检需要浏览器，本次构建环境中
  Chrome 扩展未连接，改用 `tools/css-audit.py` 覆盖其中可静态判定的部分
  （裸色值、孤儿 class、表格横向滚动容器、模拟器 id 对齐）。
  **建议发布前在真机上翻一遍 6 个模拟器页面与附录 A。**
- 模拟器为教学模型，参数与形状为教学服务，非生产系统的定量仿真。
