## F2 · 鉴别诊断表：没有照抄 Codex 的加三列方案，理由如下

Codex 的诊断我完全同意（三条证据都不能排除同组候选；「单点尖刺」组把时间轴尖刺、分片直方图、单次一致性事件混在一起）。但它开的方子——加「横轴 / 纵轴 / 切片维度」三列——我判断不是最优：

1. **坐标轴是「组」的属性，不是「行」的属性。**同一组里的候选之所以能放一起，前提就是它们在同一块面板上长得一样；把轴信息逐行重复写三列，一张 640px 最小宽的表会被压成六列窄条，可读性反而下降。我把它写进第一列的组标签里：`<b>面板名</b><br>你在看的是什么`（例：「时间轴尖刺 · 末端 QPS 或错误率的时间曲线，尖起又回落」「切片不对称 · 按分片/可用区/实例切开的直方图，一根柱子偏离其余——不是时间轴」）。轴的问题一次说清，列数不变。
2. **真正的修复在证据列的写法**：每条证据统一为「看什么 → 本卡该看到什么（加粗） → 若看到别的转向 No.X」，**每一格都点名它排除的是同组哪一张**。这正是 Codex 那条原则（每项证据必须能排除至少一个同组候选）的字面执行，只是把它落成格式约束而不是新列。

重排后 5 组 16 行（原 3 组 8 行）：

| 面板 | 候选 | 关键鉴别点（摘要） |
|---|---|---|
| 大盘平坦 | No.15 / No.03 / No.12 | 切片后有子集**请求失败** → 15；请求全成功但**同一实体两处值不同** → 03；**同一事件处理次数 ≠ 1** → 12 |
| 时间轴尖刺 | 真实入口尖峰 / No.05 / No.08 / No.02 | 入口同刻同比例尖起 → 真实；**单 key + miss 与 TTL 对齐 + 尖刺外该 key ≈0** → 05（持续高频则是热点→10，多个查空 key→04）；**周期性 + 多 key 同毫秒** → 08；**写后立读 + 打到副本 + DB 无回源尖刺** → 02 |
| 单调爬升 | 真实增长 / No.07 / No.11 | 入口跟涨 → 真实；**末端 QPS 与重试计数同步爬** → 07；**末端速率平、只有 backlog 涨、停产后线性回落** → 11 |
| 切片不对称 | No.10 / No.15 | 偏离维度是**负载**、最热÷平均 > 3（第 8 章判据）→ 10；偏离维度是**错误率/延迟**而负载持平、摘流即好 → 15 |
| 并发写者（业务台账） | No.13 / No.12 / No.17 / No.14 | **owner 持有区间重叠或旧 fencing token 后写成功** → 13（只看到 TTL 到期不算）；**同一 message-id 投递 ≥2 次** → 12；**时间戳顺序与因果矛盾 + 时钟偏差超裕量** → 17；**两地同时段都有写成功、两条互不继承版本线** → 14 |

Codex 点名的三处具体缺陷的对应修法：
- 「慢查询集中在同一 SQL/key」→ 现在要求同时满足 miss 计数跳升、与该 key TTL 对齐、尖刺前后该 key 落 DB ≈0；并明确写出「同 key 尖刺外也高频 → 持续热点，不是击穿」。
- 「锁日志附近 TTL 到期」→ 现在要求 owner 区间重叠或 fencing token 乱序写成功，并写明「只看到 TTL 到期或续租失败不算——那只是嫌疑，没有重叠 owner 就排除不了 No.12」。
- 「最热/平均显著大于 1」→ 改为引用第 8 章判据「> 3」，并把「偏离的是负载还是错误率」作为与 No.15 的分界。
- No.13 从「单点尖刺」组移出，落到它真正的鉴别语境「并发写者」组，与 12/17/14 互相排除；No.10 与 No.15 落到「切片不对称」组——与本页 06 组「分叉·不对称型」的形状分组也就对上了（原表把 No.10 放进「尖刺」是和本页自己的分组自相矛盾）。

表首说明段同步改写：明确「按你正在看的是哪块面板分组；证据若排除不了同组至少一个候选，就还不算证据」。
