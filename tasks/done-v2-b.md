## B1 · ch01 交卷 E1

位置：·2 原理段，「容量估算：三步法」公式牌之后、数字揭晓之前。不新增 `<h2>`。

**设计**：老陈只给三句业务描述（首月要撑住同量级独家开票 / 这场在售 5,000 张 / 「先把量级估对，机器我批」），
**不给** DAU、人均请求、峰值倍数、响应大小、RT。`.exercise` 要求读者交七样：
① – ⑤ 五个数各给上下界，⑥ 哪个最不确定，⑦ 把自己算出的日常峰值 QPS 换算成机器数区间——不许停在 QPS。

原有的两张 metrics 表 + 存储带宽表 + 两条 kicker，**整段移入 `.ex-model`**，作为基准答案。新增三块内容：

- **从 QPS 到机器数**：日常峰值 70 QPS 不需要换算（一台机器打哈欠），真正要换算的是开票尖峰 15,000 QPS。
  单机安全吞吐没有凭空给一个数，而是**接回本章 ·6 复盘 23:48 那次压测**（200 QPS / P99 180ms / CPU 40%）反推
  出 400–500 QPS/台，15,000 ÷ 500–400 ≈ **30–38 台**。顺带把「次日实际只跑到约 900 QPS」也在这里解释掉——
  不是估算错了，是这次只放了一个入口链接、流量被自然摊平，预算要按「被打满」的日子备，不是按「运气好」的日子备。
  这样三处数字（估算 15,000 / 压测 200 / 实际 900）互相钩住，读者点开答案不会看见互相打架的数字。
- **① 哪个假设最敏感**：论证角度不是「谁在公式里是乘数」（五个数在公式里都是线性放大器，数学上一样敏感），
  而是「谁的可信区间最宽」——DAU、人均请求有业务目标和行业经验兜底，蹲点人数相对在售票量的倍数（10 倍超卖需求）
  没开过票就是纯猜测，5 倍和 30 倍都合理，机器数区间能从 15–19 台摆到 60–75 台。
- **② 下一步压测**：拆成两件事，分别对应分母误差（单机吞吐——靠更大强度的真实压测把 400–500 QPS 收敛）
  和分子误差（真实蹲点倍数——靠一场更小的演出提前开票拿到真实比例数据）。

自评清单 5 条，覆盖：上下界是否够宽 / 是否指出最敏感假设及理由 / 是否算了日常峰值和尖峰两种场景
/ 是否换算到机器数 / 下一步验证动作是否可执行。

## B2 · ch10 D2 条件翻转（`data-f="10"` / `#v-f10`）

翻转变量：**库存的集中度**——单场 5 万个座位的单一热 key，改成 1,000 个小场次、每场 50 张、各自独立计数
（总库存仍是 5 万，只改分布，不改规模，这样翻转只隔离了「集中度」一个变量）。

**为什么它真的会翻**：D2 三个选项里，A（纯 DB）唯一的账单是「热点行成为串行瓶颈」；C（分层持有，「秒抢」的选择）
存在的全部理由，就是用 Redis 预扣去接住这个热点。1,000 个各自 50 张的场次里，任何一个 key 的并发都只是
原场景的千分之一量级，DB 条件更新单独扣一个 key 完全扛得住——**热点行这个前提本身消失了**，
所以 C 的差异化标准（挑「更热」的场次特殊处理）无从谈起，A 变成最优解，原答案 C 被翻转掉。

判词点名翻转变量，并加了一条边界提醒（1,000 场次若真的同一秒集中开票，聚合写入吞吐仍可能压过 DB 总容量，
但那是连接池/入口限流的问题，不是要不要请回 Redis 预扣的问题）——避免读者把「低并发单 key 不需要预扣」
错误泛化成「分散库存永远安全」。

## B3 · ch12 D2 条件翻转（`data-f="12"` / `#v-f12`）

翻转变量：**决胜规则**——先到先得，改成实名抽签（30 万个合格意图全部先登记，开票后统一摇号抽 6 万个名额，
与到达时间无关）。

这一题**没有直接复用 D2 的 A/B/C**（提交前让 advisor 复核过一版直接复用的设计，指出 B「快速随机拒绝」
在抽签制下语义是错的——不能真的拒绝合格意图，只是不再让顺序决定资格），改为三个贴合新前提的选项：
A 维持原方案（按到达顺序发凭证）、B 全部登记 + 开票后统一摇号、C 抽签资格仍按到达顺序限量发放再摇号（陷阱）。

**为什么它真的会翻**：D2 的队列/凭证/超时本质上都是在给「谁先到」赋予意义。规则一旦变成随机摇号，
到达顺序和中签概率脱钩，A 立刻站不住——用户排的队是纯沉没成本，系统还在为一个不再决定结果的顺序维护状态。
最优解翻转为 B。C 是刻意设的陷阱：嘴上说抽签，做法却先用到达顺序砍掉大多数人的资格，只在剩下的人里摇号——
这不是随机，只是给「先到先得」换了个说法，公平性承诺和机制对不上。

判词点名翻转变量后，额外加一段「规则翻了，但账没翻」——入口限流、热点通道、削峰队列、库存真相、幂等护栏
五道防线一个不能少，容量预算没有因为改成抽签而减少，避免读者把这次翻转误读成「文中原方案设计有问题」。

`data-f` 用了 `10`（ch10）和 `12`（ch12），与 v2-a 用的 `16`（ch16）互不冲突，全站唯一；
A11 只按页内校验配对，唯一性是我自己核对过 `git grep 'data-f='` 后确认的，没有依赖校验脚本兜底。
